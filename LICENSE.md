# Licensing scopes

Project-owned contributions in this repository are licensed by content type as follows. These scopes apply only where the contributor has the relevant rights and where a file does not carry a different explicit notice.

| Content | Scope | License |
|---|---|---|
| Hardware design source and fabrication exports | CAD, dimensioned engineering drawings, DXF/STL/STEP and manufacturing design files under hardware/ | [CERN-OHL-W-2.0](https://ohwr.org/cern_ohl_w_v2.txt) |
| Software | Python and other executable source, including future analysis scripts | [MIT](https://spdx.org/licenses/MIT.html); full notice below |
| Documentation | Markdown/text prose, protocols, manuals, BOM, and narrative technical reports, including hardware/ prose and this repository's README and instructions | [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/legalcode.en) |
| Original experimental datasets | Project-owned acquisitions and derived numerical datasets | [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/legalcode.en) |
| Project-generated scientific figures | Figures unless individually marked otherwise | [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/legalcode.en) |

Directory names alone do not override content type: hardware/BOM.md is documentation, not CAD; a Python script is software even if stored beside data. These are licensing defaults, not a statement that hardware designs, software or measurements already exist. Preserve attribution and required notices when distributing derivatives. See the [Open Hardware Repository license guidance](https://ohwr.org/licences/) for the CERN variants.

Third-party datasheets, manuals, certificates, dependencies and reference publications retain their own terms. Linking to them does not relicense them. Do not redistribute third-party files under the project defaults without appropriate rights. Contributors should identify exceptions explicitly.
